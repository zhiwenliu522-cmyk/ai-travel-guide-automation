# 多案例旅行攻略版式基线

## 适用原则

本 Agent 不以单一文档作为永久默认模板。每次制作或修改攻略时，先阅读用户此前提供且在当前任务中可访问的全部案例，识别它们的共同视觉语言与各自适用场景，再为本次行程选择合适的结构和版式。

具体模板和历史成品由使用者在本地案例目录中提供，不随公开项目包分发。任何单一案例都不是永久唯一视觉权威。

## 共同保留项

- 成品应是可直接转发给客户的中文旅行攻略，而不是内部调度表或模板化商业报告。
- 延续用户案例中的非图片品牌配色、字体、边框、清晰分区、可执行的时间与动线、自然短段落和图文阅读节奏。
- 保留案例中合理的字体气质、页面密度、分隔方式与信息颗粒度；不要为了形式整齐而套用通用商务模板。
- 永远在案例副本中编辑，不改动用户原件。完整新攻略有同城参考时，保留并重排仍适用的正文、图片和行程内容块，只清除与本次无关或已经失效的内容；不得先清空整个正文再重新生成。

## 同城内容母版规则

- 同城参考不仅控制视觉，还控制正文原句、章节、图片节奏和餐饮内容。先复制最相似主案例，再以连续内容块为单位保留、删除、复制、移动和组合。
- 内容块从有导航意义的标题或时间段开始，包含其后的景点说明、内部路线、相关原图、紧邻餐厅推荐和必要 `Tips：`，直到下一个独立行程段开始。
- 复制块时保留段落属性、运行级格式、图片关系、裁切、宽度、对齐、段前段后距和相对顺序。跨文档补充时只把视觉样式统一到主案例，不改写来源句子。
- 仅补丁式修改日期、时间、酒店起终点、交通、天气、最新预约/票价、营业状态和用户本次明确要求。其他文字逐字保留，内容块之间只写最短过渡。
- 禁止以“保留 styles.xml、主题和图片”为由重建全部正文；这种做法属于只借用外壳，不算参考复用。

## 按案例匹配，而非机械复制

- 多城、跨城、亲子、自驾、三代同游、文博城市游等，分别优先寻找结构和节奏相似的案例。
- 遇到不同案例在字体、颜色、留白、标题层级或图片配置上存在差异时，优先服从本次用户要求与相近旅行场景。有同城参考时随匹配内容块继承相关原图及其图片密度；没有同城参考时不复制跨城市旧图，但按最相近成熟案例的图文节奏补充来源可核验、可合法使用且与正文直接对应的新图。用户明确要求纯文字时不配图。
- 没有完全匹配的案例时，组合多个案例的有效元素，但成品保持一个连贯的视觉系统，不拼贴成多种风格。

## 时间段组织

- 城市慢游成品除纯到达/返程日外，从“起床、洗漱、早餐”开始完整时间轴；远郊核心日由预约入场时间倒推早餐和出发时间。
- 连续、顺路、步骤明确的游览段，优先采用“时间点 + 直接流程”：出发、到达、小景点顺序、游览动作、停留和转场连续写出。
- 当一个时段包含多个独立项目、预约、餐饮选择，或读者需要快速定位时，允许在时间点后使用短小标题、分点或分段。
- 小标题只用于导航和降低理解成本；不得仅重复时间点或景点名。以读起来像用户案例中的自然攻略为准，而非强制使用一种版式。
- 同一文档的日期标题、`🕐`、时间位数、连接号、空格和段落样式必须统一；日期标题优先只写日期，时间标题优先写自然动作，普通交通和说明文字不套用时间标题样式。
- 景点内部路线保持足够具体，但正文层级控制为路线、重点和一条必要 Tips；不通过增加“今日主线、安排原则、版本说明”制造层级。

## 验收

1. 检查是否按相似度选择了同城主案例并仅用其他同城案例补缺，而不是默认使用最新文件或跨城模板。
2. 检查时间段写法是否服务于理解和执行，而不是为满足固定结构。
3. 有同城参考时，逐项确认匹配内容块保留可识别原句、相关原图及经重新核验的紧邻餐饮/`Tips：`；没有同城参考时检查新图与正文对应、来源可用并符合成熟案例的阅读节奏。只有用户明确要求纯文字时执行纯文字模式。
4. 检查字体、颜色、边框、留白、分隔线和分页是否与主案例一致。
5. 渲染并逐页检查水印、标题孤行、文字溢出、图片错位和分页；无渲染环境时完成结构化检查并如实说明。
