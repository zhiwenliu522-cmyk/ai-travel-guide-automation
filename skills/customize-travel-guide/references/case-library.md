# 历史案例库的使用方法

## 范围

将用户在当前任务、当前工作目录或此前对话中明确提供的旅行攻略文档视为案例库。制作前尽量枚举并阅读全部可访问的案例；不要只读取最新一份，也不要默认把 Agent 自己生成的草稿或终稿当成用户案例。

## 同城市成品参考优先级

每次制作前先查找`（城市）旅游攻略成品参考`文件夹，并兼容已有的`（城市）攻略成品参考`简称。

- 没有对应城市文件夹时，继续使用原有跨案例提炼流程：借鉴风格、结构和颗粒度，不复制其他目的地的正文和图片。
- 有对应城市文件夹时，完整读取文件夹内全部成品。完整新攻略按交通方式、天数、同行人、核心景点、酒店片区、天气/季节和游玩类型选择最相似的一份主案例，再用其他同城成品补齐缺失内容；不得把最新文件自动当主案例。
- 同城案例是内容素材库，不只是版式参考。对本次仍适用的景点介绍、内部游览顺序、时间段原文、原图、原推荐餐厅和菜品，优先原样复用并重新组合；只补写必要的衔接句。
- 修改范围主要限于酒店不同造成的起点、终点、交通和片区顺序变化，用户作息与到离时间造成的时间微调，以及闭馆、天气、预约、限流、停运、交通管制、餐厅歇业等动态变化。用户本次明确需求仍高于案例。
- 原餐厅、票价、开放时间、预约与交通信息必须重新核验；餐厅还须按 [restaurant-research.md](restaurant-research.md) 复核本地评论证据、准确分店和路线适配。失效、绕路或证据不足时按规则替换，并让新增段落与案例原文保持同一语气和详细程度。
- 可复用同城成品中与新行程对应的原图，并尽量保留图片与正文的对应关系、裁切、清晰度和版面节奏；不得复用水印、Logo、背景图、个人信息、订单信息或无关图片。
- 拼接完成后统一全文标题、字体、颜色、段落间距、时间格式、emoji、图片宽度和留白，成品应详细且看不出来自多份文档。

## 完整新攻略的内容块复用

局部修改、续写和用户指定的重新排列不执行本节，只修改指定范围。完整新攻略有同城参考时必须执行：

1. 先写本次行程大纲，按每天实际顺序列出景点/体验、午餐、下午景点、晚餐和返程等槽位。
2. 对每个槽位在全部同城案例中寻找最适合的连续内容块。匹配时先看景点和路线方向，再看同行人、交通、天气/季节、当天前后顺序与作息。
3. 一个内容块应同时带走可用的时间标题、景点原文、内部路线、相关图片、紧邻餐厅和必要 `Tips：`，而不是只拿图片或只抄一句。
4. 从最相似主案例副本开始，通过保留、删除、复制、移动和组合内容块搭建新攻略。禁止清空整个正文、保留样式后重新写完所有段落。
5. 原文仅允许修改日期、时间、酒店起终点、交通、天气、最新预约/票价、营业状态和用户明确要求；其他句子逐字保留。预约句、景点介绍、推荐菜和提示也遵守同一规则。
6. 主案例没有覆盖时，继续搜索其他同城案例；所有同城案例都没有覆盖时才原创，并在内部内容块复用合同中记录原因。
7. 完成后逐槽位核对来源。若复用了同城图片但没有任何完整同城段落保持不变，或复用槽位缺少可识别的同城原段落/原句，说明只借了外壳，必须返工。

当前工作区已出现的案例名称包括黄山家庭自驾、黄山三日参考、苏州—无锡—上海五日、福州三日、南昌三日等。文件名中明确标为“Agent 风格版”、当前任务生成的“最终版”或未获用户确认的草稿，只能作为实现/核对材料，不能压过用户确认的案例。

已确认案例还包括用户修改后的 `西安五日慢游计划.docx`（2026年8月2日—6日）。同类型的城市文化慢游、亲子/学生同行、需要午休并包含单独远郊日的攻略，应优先参考它的正文节奏。本轮确认只覆盖行程结构、时间轴、景点内部路线、交通、提醒、语言和版式；用户新增的具体餐厅、酒店及酒店图片不作为本轮对 Agent 原稿的优劣判断依据。

该案例提炼出的稳定规则：

- 前部按固定顺序放置简短预约、天气与穿着携带建议、可选的特殊注意事项和“景点介绍”，再进入“具体行程”；景点介绍只写已安排景点并按行程顺序排列，不写成长篇方案说明、百科或内部风险报告。
- 每日从起床、洗漱、早餐开始；远郊日可以明显早起，但早餐、车程、停车/步行、安检和预约入场必须形成完整时间链。
- 日期标题保持短，时间标题直接写动作；删除“今日主线、安排原则、本版本重点”等重复解释。
- 博物馆和大型景区保留准确的内部参观顺序、分区停留和重点看点，整体颗粒度以“能照着走但不逐分钟讲解”为准。
- 注意事项优先压缩为一次 `Tips：`；保留必要减法，不重复写同一风险。
- 交付前必须单独检查预约场次与行程时间、地铁线路与换乘、远郊缓冲、日期/时间样式和错别字。

本轮新增确认的可直接交付成品还包括：

- `南浔乌镇苏州杭州六日安排.docx`：适合作为多城串联、频繁换城且需要酒店/城际交通说明的参考。稳定做法是前部独立放预订、天气、酒店与换城信息，具体行程写清车站、行李、入住衔接；餐厅、拍照点、夜游、酒吧或商圈只在对应城市和时间段出现，地图与交通截图服务于转场决策。
- `昆明五日自然轻松游攻略.docx`：适合作为自然景观、轻松作息与城市周边组合的参考。稳定做法是把机场到酒店、酒店周边早餐晚餐放进特殊说明，用地图辅助路线；每日保留午餐、休息和醒目的 `Tips：`，章节色块、页码与景点图形成清楚节奏。
- `武汉十四日漫游计划.docx`：适合作为长住慢游、低强度、多片区分日探索的参考。稳定做法是每一天保持早餐、午餐、午休、晚餐和回酒店的完整链条，地铁与短途接驳写具体，图片约每1—2页辅助一个重点区域，同时按需加入市场、江滩、夜景、演出或商圈。

三份新增成品共同确认的规则：完整新攻略默认是图文客户成品；前部信息、景点介绍和逐日行程齐全；每个主要用餐窗口出现与路线对应的具体门店；多城转场、酒店附近餐饮、午休和夜间安排按场景补齐；图片紧跟对应内容并保持稳定阅读节奏。案例中的错别字、重复编号、水印、过期价格和旧餐厅信息不继承，餐厅候选必须重新研究和地图核验。

## 提炼流程

1. 分别记录每份案例的目的地、交通方式、天数、同行人、核心景点、酒店片区、天气/季节、章节顺序、文字颗粒度与图片配置；同城成品的相关原文和原图可以继承，跨城市案例内容只作风格记录，所有水印均不得继承。
2. 完整新攻略按上述维度选一份最相似主案例，并记录选择理由；其他同城案例只补主案例缺失的槽位。
3. 建立行程槽位与来源内容块的对应关系，写入 [block-reuse-contract.md](block-reuse-contract.md) 规定的内部合同。
4. 用户本次明确指定某份案例或某项格式时，该要求优先于案例库中的一般规律。

## 禁止项

- 不以单一案例永久锁死字体、颜色、标题层级或时间段格式；同城市成品存在时可按其图片密度复用相关原图，不存在时也按最相近成熟案例的图文节奏补充来源可用的新图，用户明确要求纯文字时除外。
- 不因为案例较多而把多个文档的封面、色彩、表格或标题体系拼到同一份攻略里。
- 不把同城成品当成只有字体、颜色和图片的样式壳；不得复用了图片却把对应原文全部重写。
- 不复制跨城市案例的旧目的地正文、价格、预约规则、图片或行程信息。同城市案例可复用仍适用的正文、图片和餐厅推荐，但动态信息必须重新核验。
